# Word 文档制作与编辑

## 工具链

| 工具 | 用途 |
|---|---|
| `write_docx(path, doc \| doc_file \| markdown, title?, style?)` | 生成/重建 .docx |
| `read_docx(path)` | 读回 Doc JSON 源（自家文件无损；外来文件近似导入并抽取图片） |
| `edit_docx(path, ops)` | 结构化编辑已有 .docx（改块/增删块/全文替换/换样式） |

图片来源只能是：工作区已有文件（用户上传、`pdf_to_images` 的 `pdf_images/` 产物、`read_docx` 抽取的 `docx_images/` 产物）、data URL 或 http(s) 链接。`.svg` 文件可直接引用（导出时自动栅格化）；需要照片级素材用 `download_file` 下载到工作区；需要图标/示意图用 `write_svg` 生成（见 svg 技能）。**禁止编造不存在的图片路径**——先用 list_files 确认。

## 工作流 A：新建文档

1. **先定结构**：封面(可选) → 目录(≥8 块长文用) → 分级标题组织章节 → 正文/列表/表格/图片。标题是结论（"上半年营收 +18%"），正文每段一句话观点 + 论据。
2. **写 Doc JSON**。速查最小例：

```json
{"title":"Q2 经营分析报告","author":"经营分析组","cover":true,"toc":true,"blocks":[
 {"type":"heading","level":1,"text":"一、总体经营情况"},
 {"type":"paragraph","text":"上半年营收 **1.2 亿元**，同比 *+18%*，主要来自华东区。图 1 展示了月度趋势。"},
 {"type":"image","src":"photos/trend.png","caption":"图 1 月度营收趋势（来源：财务中台）","width":0.8},
 {"type":"heading","level":2,"text":"1.1 分渠道表现"},
 {"type":"table","headers":["渠道","营收","同比"],"rows":[["线上","7,000 万","+22%"],["线下","5,000 万","+11%"]]},
 {"type":"list","ordered":false,"items":[{"text":"直播带货 GMV 2,300 万","level":0},{"text":"新开门店 12 家","level":1}]},
 {"type":"quote","text":"增长的本质是复利。"}]}
```

3. **生成**：≤20 块直接 `write_docx` 传 `doc`；更长先 `write_file("doc.json", …)` 分块写好（后续 `append_file` 续写），再 `write_docx` 传 `doc_file:"doc.json"`。
4. **自检**（生成后必做，见文末清单）；有问题用 `edit_docx` 修正或改 doc 后重新导出。

## 工作流 B：编辑已有文档

1. `read_docx(path)` 读回源（外来文件注意提示中的近似导入说明与抽取的图片清单）。
2. 小改：`edit_docx` 用 `replace_text`（全文改词）/`update_block`（改单块）/`add_block`/`delete_block`/`move_block`。
3. 换风格：`edit_docx` 传 `{"op":"set_style","style":"academic"}`；改封面/目录开关用 `set_cover`/`set_toc`。
4. **仿制模板**（用户给了一份 docx 说"照这个样式/结构做"）：先 `read_docx` 读模板，**分别提取结构与风格**——结构：章节划分/封面目录/表格图片位置；风格：标题层级、正文密度、配色（外来文件近似导入，样式细节看文字/排版描述）。再用工作流 A 用 Doc JSON 重建（重建比硬改模板更可控、排版更规范）。改完要保留模板的**内容完整性**：章节齐全、数据一致。
5. 外来文件改前会自动备份 `*_原版备份.docx`，不要删它。

## 能力边界（重要：不要承诺做不到的功能）

**支持**：分级标题(H1~H6)、正文/列表/表格/图片/引用/代码块/公式(OMML)/封面/目录(静态文本)/分页/分隔线；三种样式预设；图片支持工作区路径、data URL、http、svg 自动栅格化。

**不支持**（用户要求时**明确说明做不到**，并给替代方案）：
- 修订/批注（track changes/comments）
- 页眉页脚、页码、水印、脚注尾注
- 自动更新目录（我们生成的是静态目录文本；Word 里可按 F9 更新域，但页码不会自动刷新）
- 邮件合并、宏、VBA、文档保护/密码、嵌入字体
- 复杂分节（不同章节不同页边距/纸张方向）、多栏排版
- 文字环绕的浮动图片（只支持行内插图）

遇到这些需求：说明"当前版本不支持 X，已改为 Y（近似替代）"或用纯文本表达（如脚注改为括号注）。

## 块速选

| 块类型 | 何时用 |
|---|---|
| heading(1~6) | 章节标题（自动按级别区分字号：H1 22pt → H6 12pt，黑体加粗） |
| paragraph | 正文段（12pt 宋体，1.5 倍行距，首行缩进 2 字符） |
| list | 要点列表（ordered:true 有序 / false 无序；条目 level 0/1 两级缩进） |
| table | 结构化数据（≤20 列；首行为表头，自动加底色） |
| image | 插图（src 工作区路径/data URL/http；width 0~1 页宽比例；caption 题注） |
| quote | 引用/金句（左侧竖线样式） |
| code | 代码块（等宽字体 + 灰底） |
| divider / pagebreak | 分隔线 / 分页 |

行内格式（在文本字段里直接用）：`**粗体**` `*斜体*` `` `代码` `` `[链接](url)` `![说明](src)` `$公式$` `~~删除线~~`。

字段级语法（必填项、table/image 全字段、样式预设）：`load_skill("docx","reference/doc-dsl.md")`。

## 排版规范（摘要，全文见 reference/design-guide.md）

- **标题是结论**：H1 写结论句（"营收 +18%"），不用"经营情况"这类空泛词；H2/H3 层层递进。
- **段落**：一段一个观点；长文每章 3~6 段，不要一段塞满整屏。
- **表格**：数据必须来自工作区资料，加 caption 注明来源；超过 10 行考虑拆表或只列关键指标。
- **图片**：不凑数——没有合适图片就用纯文字，好过无关配图；图片必须真实存在且清晰。
- **禁用 AI 腔**（"赋能""闭环""综上所述""不是X而是Y"）；用具体名词和数字。
- 默认样式 default（蓝色标题）适合商务报告；academic（黑标题、素净）适合论文/学术；minimal（灰标题）适合内部备忘。

## 交付前自检清单

> **QA 心态**：第一次输出几乎总有问题——按"找 bug"的心态复验，一次就找到 0 个问题说明没认真找；**至少完成一轮「发现问题→修复→复验受影响部分」再交付**。

- [ ] 结构完整（有标题；长文有封面/目录；H1~H6 层级不乱跳）？
- [ ] 标题是结论句？正文一段一个观点、无 AI 腔？
- [ ] 无占位残留：全文不含 xxxx/lorem/ipsum/占位/TODO/TBD 之类？
- [ ] 表格/图片的 caption 标注了来源？数字与工作区资料一致？
- [ ] 引用的图片路径都真实存在（list_files 确认过）？
- [ ] read_docx 或 read_file 抽查过最终文件内容？
- [ ] 无编造数据、无编造图片路径？
