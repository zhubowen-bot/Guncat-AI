# PPT 设计规范

面向工作模式生成演示文稿的质量底线。按此执行，不依赖默认审美。

## 1. 页面节奏

典型 10~20 页结构：

```
cover → toc(≥6页时) → section → 内容页×N → section → 内容页×N → end
```

- 内容页是大头；每个 section 下 2~5 页内容，不要一节一页。
- 一页一个任务：一页只讲一个观点/一组数据/一张图。写不出这页的任务就删掉它。
- 数据密集内容优先 table/chart，不要用要点列表复述表格。

## 2. 标题即结论

- 内容页标题写判断句，不写话题词："营收同比 +18%，超预期" ✅；"营收情况" ❌。
- 标题 ≤20 字；超了说明页面承载过多，拆页。

## 3. 要点纪律

- 每页一级要点 3~7 条，每条一句话（≤25 字）；二级要点做补充事实或数据。
- 要点并行：同一页内要点语法结构一致（都是短句或都是"指标+数值"）。
- 禁止把整段文字塞进要点；成段的论述交给 docx，不是 pptx。

## 4. 图表语言

- 选型：时间趋势 → line；类目对比 → bar；构成占比 → pie/doughnut（≤5 块）；累计 → area。
- 一个图表一个信息点； series ≤3 个（超过就拆图）。
- categories 是类目名（短），values 是数值；单位写进 series name 或 caption。
- **数据必须来自工作区文件/搜索记录，禁止编造**；caption 标注来源与口径。
- 数字用阿拉伯数字，金额给单位（万/亿），比例给百分号。

## 5. 表格纪律

- ≤20 行、≤6 列；超出就拆页或转 chart。
- 首行是表头；行内同类信息对齐；长文本单元格压缩为短语。

## 6. 图片使用

- 优先级：用户提供的 > 工作区已有（pdf_to_images 产物等）> http(s) 直链；没有合适的就不放图。
- 图片不凑数：与内容无关的装饰图会拉低质量。
- 全幅图（image-full）配 overlay 0.4~0.6 的封面用法；image-text 时图占 40%，文字要点在另一侧。
- 引用 PDF 图表截图时在 caption 标注出处（"来源：《xx 报告》P12"）。

## 7. 文风禁令

- 禁止：闭环、赋能、抓手、颗粒度、组合拳、底层逻辑、 综上所述。
- 禁止 AI 腔："不是 X，而是 Y"句式滥用、"总而言之"、"值得注意的是"堆叠。
- 禁止空话："取得了良好的效果"、"迈上新台阶"——换成数字或事实。
- 全文用用户的语言；中文 deck 内的专有名词保留原文。

## 8. 场景速配

| 场景 | 主题建议 | 版式侧重 |
|---|---|---|
| 工作汇报/经营复盘 | brand-blue / graphite | content + chart + table |
| 方案/商业计划 | forest / sunset | cover+section 节奏 + two-col + table |
| 技术分享 | midnight / violet | content + image-text + custom |
| 教学/培训 | ivory / brand-blue | content + two-col + image |
| 发布/路演 | crimson / sunset | 大图 cover + chart + quote |

## 9. 一致性检查（交付前）

- 全册只用一个 theme；不要每页混用背景色。
- 同级标题字号一致（由版式保证，勿在 custom 里乱设 size）。
- 时间口径统一（"Q3"/"7-9月" 二选一），货币单位统一。
- notes 可为关键页补充口径说明（不会被观众看到）。
