# SVG 绘制规范（craft）

面向栅格化预览与文档引用的工程规范。逐条遵守，预览是最终裁判。

## 1. 文件骨架（硬性要求）

```svg
<svg xmlns="http://www.w3.org/2000/svg" width="96" height="96" viewBox="0 0 24 24" fill="none"
     stroke="#333F50" stroke-width="2" stroke-linecap="round" stroke-linejoin="round">
  <title>图标名</title>
  <!-- 图形元素 -->
</svg>
```

- `xmlns="http://www.w3.org/2000/svg"` 必须有——缺失时栅格化直接失败；
- **`width`/`height` 与 `viewBox` 都要有**——实机栅格引擎要求根元素带显式 width/height，只有 viewBox 会解码失败（工具会在缺失时自动按 viewBox 补齐，但模板始终显式携带，保持源文件自描述、对其他查看器友好）。width/height 通常取 viewBox 尺寸的整数倍（如 24 网格 → 96×96）；
- `<script>`、`javascript:` 引用会被工具直接拒绝；外部 `<image href="http…">`、外部字体引用不要用。

## 2. 视框与网格

- **图标用 24×24 网格**（描边 2px、圆帽圆角），这是 iconfont/Lucide/Feather 的通用规格，视觉密度最稳；
- 插画/示意图用 480×360、512×320 这类 4:3 / 16:10 比例；放进 PPT 正文区的图按版式空隙定比例（如 960×540 的局部 → 480×270）；
- 关键坐标落在整数或 .5 上；元素间留白 ≥ 视框宽度的 4%；
- 预览时把图缩到 48px 宽还想看清的（图标类），说明元素够简洁；缩看一团黑的，简化。

## 3. path 优先，shape 次之，text 慎用

- **图标/符号一律 path**（`M/L/H/V/C/A/Q/Z`）。基础形状 `<rect>/<circle>/<line>/<polyline>` 适合示意图框架；
- `<text>` 依赖设备字体：字宽因平台而异，会截断、错位。规则：
  - 示意图/流程图里的少量标签可以用 `<text>`（font-family 写 `sans-serif`），但**必须预览确认**；
  - 渲染异常（截断/换行错位）就把文字转成 path 或干脆去掉文字（含义放 PPT 的 bullets/notes 里说）；
  - 禁止用 `<text>` 做大段文案——那是版式（PPT 文本框）的职责。
- `text-anchor="middle"` + 放在目标框中心是防截断的标准姿势。

## 4. 描边风格与填充

- 图标：`fill="none"` + `stroke="#333F50" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"`；
- 强调变体：整图加深色填充 `<path fill="#0A7AFF" stroke="none">`；
- 描边宽度相对视框：24 网格用 2；480 视框用 8~12，等比放大，不要照搬 2；
- 深色背景页面上的图形用浅色笔画（#E2E8F0 系）；背景透明默认可用，但放深色页时自查对比度。

## 5. 配色纪律

- 放进 PPT 时对齐主题色（brand-blue 主色 #0A7AFF、midnight 用 #38BDF8……见 ppt 技能 themes）；
- 信息图的语义色固定：成功/正向 #3DBE64，警示 #E9A23B，风险/负向 #E05252——全册一致；
- 渐变（`<linearGradient>`）与滤镜（`<filter>`）能用但慎用：预览确认渲染正常再保留，效果不对就退回纯色。

## 6. 复杂度与场景分级（规则按场景适用）

- **线框图标 / 商务信息图**：上述纪律全部适用——主色 ≤3；图标 ≤10 个元素、示意图 ≤40、信息图 ≤80；
- **卡通插画 / 吉祥物 / 主题插图**：授权放宽——4~6 色、30+ 元素可接受（"图标+小插画"混合场景的合理形态）；仍须：预览自检、避免 `<text>`、结构用 `<g>` 分组、无 `<script>`；
- 超限前先问一句：这页信息是否该拆成两个图，或改用 PPT 的 chart/table 版式表达。

## 7. 结构与复用

- 元素分组 `<g>` 带语义命名（如 `<!-- 节点 -->`），便于后续局部修改；
- 数字、连线等重复结构写清楚间距规律（等距、对齐网格），预览里错位 1px 在 24 网格上都很显眼；
- 复用形状用 `<defs><g id="x">` + `<use href="#x">`，减少重复坐标错误。

## 8. 可访问性

- 图标/信息图在根元素后加 `<title>名称</title>`（模板已内置）——屏幕阅读器可读出内容，成本一行；
- 纯装饰图形（封面几何点缀）可省略 `<title>`。

## 9. 预览即真相

`view_image` 看到的就是最终交付效果（PPT 引用 .svg 时按 1024px 宽栅格化）。所以：

- 一切"应该没问题"的判断都作废，以预览为准；
- **解码类失败按"最小复现 → 增量叠加"定位**：先用仅含一个 `<rect>` 的最小 SVG 走通管线，成功后逐步叠加元素二分定位——刚写入的文件不存在"语法损坏"，读回全文验证语法价值低；
- 预览失败的报错会指明方向（xmlns 缺失、渐变/滤镜兼容性等）——按提示修；
- 迭代不要新增文件名，覆盖原路径；合格后不要再动它。
